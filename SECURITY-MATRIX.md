# Security matrix

For every security-sensitive exercise and capstone: what it protects, where the trust boundary is, who may do what,
how it typically fails, and the negative tests that pin each failure. Teaching implementations are simplified; each
exercise README's *Production caveats* says what to change before production, and the book's Production readiness
panels say what each example does not protect against. `python scripts/security_matrix.py` (run by
`check.py --solutions`) fails if a named test no longer exists.

The negative-test classes: cross-tenant access, invalid or expired credentials, replayed requests, prompt injection,
unauthorized tool execution, and timeouts, bounded retries, audit trails, rate or budget limits and fail-closed
behavior where they apply. Gaps are stated in the failure-modes column as *not tested* or *documented limitation*.
