# Forward Deployed Engineer: exercises & capstones

100 hands-on exercises and 6 capstone engagements for engineers preparing for Forward Deployed
Engineer (FDE) roles: building, integrating and running AI systems inside customers' environments, and owning the
customer outcome. Every exercise ships with a starter, tests and a reference solution, and runs **offline**: a
deterministic fake model stands in for the LLM, so no API key is needed.

## Quick start
```bash
pip install -r requirements.txt
python scripts/check.py --solutions          # all reference solutions: green
python scripts/run_all.py --docker           # the same in Docker, with a per-exercise report in output/
pytest exercises/ch02-discovery-and-scoping/ex01-engagement-charter   # one exercise: starts red, make it green
```
Requirements: Python 3.11+, and Node 22.18+ for the TypeScript exercises (Node 24 LTS recommended; native type
stripping, no npm install).

Run the exercises for one chapter of the book with `python scripts/check.py --chapter 10` (add `--solutions` for the
reference solutions).

`scripts/run_all.py` runs every exercise and capstone solution one suite at a time and checks the results: every
test declared in a suite ran and passed, and the starter fails at least one of them. With `--docker` it builds
`docker/runner.Dockerfile` (CUDA base, Python 3.12, Node 24) and runs inside it with `--gpus all`; the exercises are
CPU-only, so the GPU is reported in `output/environment.txt` but not needed. Results go to `output/`, laid out like
`exercises/` and `capstones/`, with `output/summary.md` on top.

## How it works
- `exercises/chNN-<chapter>/<exercise>/`, one folder per book chapter: `README.md` (scenario + task), `starter.*`,
  tests, `meta.json`, and `HINTS.md`: three progressive hints plus a table mapping each test to its most likely cause
  of failure.
- Every exercise and capstone README ends with **Run and verify**, the same contract everywhere: prerequisites, the
  command to run, the expected output against the starter and when done, how to check the reference solution, the
  tests, common failures, how to tell whether a failure is your environment, your code or a defect in the published
  solution, cleanup, and production caveats (what the exercise deliberately simplifies).
- `solutions/` mirrors the tree with reference implementations. Peek only after you've tried the hints.
- `pytest --solutions <path>` runs the same tests against the reference solution.
- `capstones/<cN>/`: multi-day engagements with `starter/` packages, deliverable templates, shared `data/` and tests.
  All six are assessed with one [rubric](capstones/RUBRIC.md): gates first, then a weighted score.
- `playbook/`: [copyable templates](playbook/README.md) for the engagement artifacts the book teaches, in five packs
  (discovery, solution design, delivery, production readiness, handover).
- `interview/`: [127 interview questions with model answers](interview/questions-and-answers.md), seven or eight
  per book chapter, tagged technical, coding, debugging, system design, customer scenario or behavioral.
- `fde_kit/`: the offline `FakeLLM`, an optional `AnthropicLLM` adapter (`FDE_LIVE=1`), and text utilities.
- [`TRACEABILITY.md`](TRACEABILITY.md): every exercise and capstone with its book chapter, path, command and
  expected result, regenerated by each full run.
- [`SECURITY-MATRIX.md`](SECURITY-MATRIX.md): for each security-sensitive exercise, its assets, trust boundary,
  identities and permissions, failure modes and the negative tests that pin them.
- `reader-validation/`: the [protocol](reader-validation/README.md) for testing the exercises with target readers.
- `research/`: the [job-posting analysis](research/README.md) behind Chapters 1 and 17: a per-posting index (no
  posting text), the classification rules, and a script that recomputes every published figure.
- `scripts/`: `check.py` (all tests, or `--chapter N`), `run_all.py` (every suite, checked, report in `output/`),
  `starters_red.py` (every suite starts red), `currency_check.py` (dated facts re-checked before a release), the linters `spec_lint.py`, `hints_lint.py` and `contract_lint.py`
  (every README has a complete Run and verify section), `traceability.py` and `security_matrix.py` (both maps stay
  true), `verify_release.py` (a release checked from an anonymous clean clone, with `--docker` and `--offline`), and
  `export_learner.py`.

## Recommended order (the book's five parts)
The chapter folders follow the book, so working through them in number order is the recommended path; every capstone
comes after the exercises it builds on. Go at your own pace: the order matters more than the speed.

| Part | Exercises | Then |
|---|---|---|
| **I · The FDE role and customer engagement** | ex01–ex08, ex68, ex69, ex81, ex82, ex84 | |
| **II · Engineering foundations** | ex09–ex15 · ex16–ex21, ex78 · ex22–ex26, ex77, ex80, ex92 · ex27–ex30, ex91 | |
| **III · Building generative AI systems** | ex95–ex98 (prompt engineering) · ex31–ex36, ex86 · ex37–ex41, ex88 · ex42–ex48, ex79, ex85 · ex49–ex52, ex99, ex100 · ex53–ex56, ex83, ex89, ex93 | Capstones 1, 2, 3 |
| **IV · Production operations (LLMOps)** | ex57–ex66, ex76, ex94 · ex67, ex70–ex75, ex87 | Capstone 4 |
| **V · Engagement leadership and careers** | ex90 | Capstones 5, 6 |

Every README has a **Prompt kit**: a tutor prompt to learn the concepts, a build spec you can hand to a coding agent,
and a review prompt. Use the agent the way you would on a customer site: you own the result, so review what it writes.

## Using a real model
Exercises accept any client with `complete(messages, system=..., tools=..., **kw)`. `fde_kit.AnthropicLLM` wraps the
official `anthropic` SDK (default model `claude-opus-5-5`, with server-side refusal fallbacks enabled). Install `anthropic`
and set credentials, then pass `AnthropicLLM()` where the tests pass a `FakeLLM`. Outputs will vary, which is
what the evaluation exercises are for.
